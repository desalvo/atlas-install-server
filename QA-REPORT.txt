Changes validated in r4
-----------------------
- Fixed IGTF trust-store initialization: bundle layout is discovered recursively.
- Trust anchors are merged in staging, validated, rehashed with `openssl rehash`, then promoted.
- OpenSSL hash entries are validated after rehash, without assuming regular-file `*.0` entries.
- Existing CRLs are preserved while trust anchors are replaced.
- Periodic IGTF refresh is automatic in the serving container:
  * refresh/check interval: 21600 seconds (6 h)
  * trust-bundle maximum age: 86400 seconds (24 h)
  * CRL refresh: every updater invocation
  * successful periodic refresh: graceful Apache reload
  * failed refresh: previous active trust store remains intact
- Kubernetes manifest and Docker Compose expose the new IGTF refresh settings.
- Kubernetes wizard detects existing bootstrap/TLS Secrets and asks before changing them.
- Existing Secret update default is NO; second runs therefore preserve credentials/certificates.
- Existing bootstrap non-secret values become defaults only when update is explicitly selected.
- Existing DB passwords are preserved by blank password input.
- Initial host certificate/key paths are saved locally and reused until explicitly changed.
- Identical TLS files are detected; no Secret update or Deployment restart is performed.
- A real TLS change triggers Deployment restart so Apache loads the new certificate.
- Generated manifests/state use compare-before-write behavior.
